# Reader Workbench · 浏览器阅读工作台

<!-- impeccable:product-schema 1 -->

## Platform

web

## Users

- 主要用户是进行个人学习与科研的读者，使用论文、课件及专业资料开展阅读、理解、分析与整理。
- 使用场景是个人电脑上的本地阅读工作台：原文保持可见，主对话承载持续分析，临时对话处理阅读中出现的局部疑问。
- 该用户定位及下述长期产品边界由用户于 2026-10-14 确认；本记录仅覆盖 `apps/web`。

## Product Purpose

在同一工作区内同时阅读文档、开展主要分析并随时追问，减少在原文和对话之间切换的负担，让局部问题不打断主阅读任务。

成功意味着用户能打开真实文档、连接自己配置的模型、获得可回到原文核对的回答，并在保持主记忆完整的情况下持续追问；生成的阅读材料能在所属工作区找到并打开。

## Positioning

产品机制是本地工作区、并行的文档与双对话空间，以及可复用的逐页文档记忆。临时追问读取最新已完成的主记忆并保留自己的追问链，答案不回写主对话。逐页阅读记忆供后续问题复用，需要时再回看指定页。

上述机制是产品事实，不构成独占性、回答准确率或相对其他产品性能的声明。

## Operating Context

- 使用本地 Node.js 服务及桌面浏览器；当前平台范围为 Windows、macOS、Linux。窄浏览器窗口仍属于 Web，不等同于独立 iOS/Android 应用适配。
- 用户先选择本机工作区，再浏览目录、打开文件、配置模型并提问。已有文件在原位置读取，生成文件默认保存到 `outputs/<session>/`；缓存、记忆与历史位于工作区 `.reader-workbench/`。
- 文档、主对话与临时对话可并排或分割排列，各有独立滚动与内容缩放。手动布局不因窗口方向自动改写。
- 用户自配模型服务地址、模型、API Key 和能力。连接、密钥、提示词、模型选择、思考档位及截图快捷键位于用户配置目录的 `agent/`，所有工作区共用；主对话可归档并恢复，历史与临时分支保留。使用远程模型时，参与提问的文字、记忆和所需页图像会发送至该服务，界面须准确说明这一点。
- 已有技术实现为 React、TypeScript、Vite 和同源 HTTP API。根目录 `npm run build` 构建应用，`npm start` 启动本地服务，默认端口为 4317；Windows 另有 `Start-Reader.ps1` 入口。

## Capabilities and Constraints

- 阅读与预览 Markdown、PDF、Word、PowerPoint、图片及生成文件。Office 原版页面预览依赖本机 LibreOffice 与字体；无预览器的文件提供明确的格式信息和下载入口。
- 支持选字后询问、区域截图及来源跳转；答案中的页码或定位须有可靠来源，不伪造不存在的定位。
- 文档记忆按用户设置的首读范围记录逐页内容、页码与不确定项，支持公式/图表/术语检索、回原文、补读及重建。PDF/PPT 图像预读需要视觉模型；Markdown/Word 使用文本。当前运行固定文档版本与页码范围，选区提问不触发整篇预读。
- 文档翻译是独立插件能力，支持原生文本层与选中文字；先预览、下载，明确另存才写新文件。Markdown 保留结构与资源，Word 保留可编辑 XML，PDF/PPT 为原页与译文伴随页对照；扫描页不默认 OCR，Word 预览页子集不承诺映射到 DOCX。
- 主对话与临时对话独立保留历史。临时分支每次读取最新已完成的主记忆，不纳入尚未完成的主回答，不回写主记忆。
- 原文件保留，转换及生成操作不覆盖原件。工作区之间隔离文件、历史、记忆与状态。
- 临时提问默认只读；生成文件由用户逐次授权。生成结果只有成功落盘后才显示为已保存。
- 两个输入框支持本地离线语音转写；转写先成为可编辑草稿，用户发送后才调用模型。
- 插件和外部 MCP 为已有扩展入口。前端复用服务端能力与契约，不另建不一致的业务状态。
- 当前不做公开互联网多用户服务、账号计费、协同编辑或完整 Office 编辑器；当前没有独立 iOS/Android 应用交付要求。
- 面向个人学习与科研的更细分任务优先级、额外无障碍标准及新平台要求尚未决定，后续按具体需求确认。

## Product Principles

1. 让原文、主要分析与局部追问能同时进行，保持阅读任务的连续性。
2. 保持主记忆与临时追问的边界，复用已完成的上下文而不污染主记录。
3. 尊重本地工作区和原文件，清楚显示输出位置、写入授权与数据发送范围。
4. 让来源、能力条件、不确定内容和运行状态可核对，不把演示、失败或未验证能力呈现为成功。
5. 保留用户对布局、缩放、模型连接和提问时机的控制。
