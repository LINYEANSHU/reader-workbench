# 工作区关联记忆（本地试验）

本功能尚未发布。它使用 Cognee 1.6.5，把当前工作区及子目录中的可读取资料建立关联，无需课程命名、标签或手工分类。现有逐页阅读记忆继续独立工作。

## 准备一次，之后自动使用

需要 Python 3.10–3.14，推荐 3.11；安装器优先使用 uv 创建独立环境，也支持已有 Python 的 venv/pip。源码目录执行：

```sh
node scripts/setup-workspace-memory.mjs
```

使用自定义配置目录时，向安装器传入与 `reader-workbench web --config-dir` 相同的 `--config-dir`。可选 `--runtime-dir` 指定私有运行目录，`--python` 指定 uv 的 Python 版本或解释器路径。

安装器下载外置 Python 依赖、GLiNER 本地抽取模型和多语言嵌入模型，实际加载成功后才保存就绪标记和用户级解释器设置。模型权重不进入 Git/npm 包。此步骤需要网络；正常建图和检索设置为本地模型与离线缓存，不读取项目 `.env`，不使用现有模型 API Key，关闭 Cognee 遥测。

重启工作台并选择工作区，侧栏“工作区记忆”会显示进度、去重数量及未关联资料。资料自动发现；状态查看和普通提问会触发最多每 30 秒一次的更新检查，也可手动更新。索引更新时问题继续使用已选资料，不等候整个图谱重建。构建完成后，普通提问可自动得到其他文件的少量关联证据；选区提问保持仅选区范围。

侧栏可检索知识、查看出处并跳回原文，可关闭自动关联。开关为用户级设置；记忆记录保存在各自工作区的本地数据库，图谱保存在 `.reader-workbench/knowledge` 中。默认输出目录不自动再次入库，防止生成内容循环放大。

## 如何控制冗余和过时内容

- 相同的规范化文字共享一个检索项，保留各自文件、版本及页码来源。
- 文档版本未变化时复用现有快照；内容变化后发布新的完整图谱快照，当前试验尚未实现单段增量重建。
- 每次回答只附少量检索结果，最多 8 段，并受上下文预算约束；不把整个工作区塞入模型。
- 使用证据前重新检查文件版本、排除规则和当前阅读页码计划。被修改、删除、新排除或缩小阅读范围的内容立即失效。
- 模型只接收已验证的来源 ID 对应原文；索引和召回不代表模型已经正确理解所有图形或已经验证结论。

## 当前边界

支持现有解析器可读取的 Markdown、纯文本、PDF、Word、PowerPoint，以及图片文件的发现。图像或扫描页没有原文文字时，状态明确显示尚无可索引证据，不自动 OCR，也不声称已理解图片。Office 仍依赖 LibreOffice。

默认不纳入隐藏目录、依赖、构建目录、`outputs`、凭据类文件名及符号链接，尊重各级 `.gitignore` 和可选 `.readerignore`。一次发现最多 5000 份、单份最多 64 MiB、目录条目最多 20000；达到上限会显示未完成范围。

Cognee 当前 GLiNER 抽取路径由上游标为 demo。真实中英文小样通过不代表复杂数学关系、所有中文知识或大型工作区的质量已经验收。Windows 原生图库使用同一存储目录内的相对路径，兼容工作区名称中的中文与空格，不依赖 Windows 短路径，也不把图谱移出工作区。

## API

以下接口均需现有本机认证与所属工作区授权：

- `GET /api/v1/workspaces/:id/memory`：状态、覆盖范围、去重与未关联资料。
- `PUT /api/v1/workspaces/:id/memory`：`{"enabled":false}` 或 `true`。
- `POST /api/v1/workspaces/:id/memory/sync`：启动后台更新，返回 202。
- `GET /api/v1/workspaces/:id/memory/search?query=...`：有原文锚点的检索项。

实际引擎测试：先准备独立运行库，再设置 `READER_TEST_COGNEE` 为含 `agent/workspace-memory.json` 的配置目录，运行 `npx vitest run tests/integration/cognee-runtime.test.ts`。普通回归不会自动下载模型或调用实际 Cognee。
