# 逐页图像阅读与本地文档记忆插件

日期：2026-10-12。状态：待用户审阅设计；尚未实现。

## 用户确定的目标

使用已配置的 `deepseek-flash`，保留现有 OpenAI 兼容调用方式。新增可安装、可启停的插件，把 PDF 或已转为 PDF 的 Office 文档逐页渲染为图片。用户第一次对该文档提问时，先把所有页图像交给模型阅读，让模型返回可序列化的阅读记忆，保存到所属工作区。本轮问题随后根据记忆回答；后续问题默认发送该记忆与必要的对话历史，不重复发送全部页图像。

原始文件、页图像、原文文字、阅读记忆和会话历史均保存在本地。文档记忆是应用维护的有来源的文本/JSON，不是模型隐藏状态、思考过程、权重或服务端持久会话。上传及打开文件只做本地解析和图片准备，首次对话才调用模型。运行中出现会影响约定行为的问题，及时向用户询问。

## 现状与最小架构扩展

现有 PDF 适配器已经提取所有页文字，`DocumentService.readPage` 能按页码生成图片缓存。现有 `MemoryProvider` 只摘要对话，`ContextBuilder` 每次检索少量原文并默认发送第一页图像。模型适配器还统一限制一次最多四张图像。不能仅增加一个未被运行消费的插件就声称功能接通。

采用新增 `documentMemory` 插件能力的方案，配套受控宿主接口。核心只提供调用、权限、文档版本、模型租约、持久化与预算桥接；逐页读取、批次策略、记忆提示词和记忆检索逻辑放在 `plugins/visual-document-memory/`。继续使用本项目 SDK，不宣称兼容 DeepSeek Harness 插件格式。

备选方案：用现有 context 插件直接访问磁盘和另建模型连接，会重复凭据管理并绕开运行取消/模型租约；把全部逻辑写进核心，会使文档阅读策略无法独立启停。两者均不采用。

## 插件与宿主契约

- 插件注册一个文档记忆 provider，通过 `prepare` 在已授权的提问运行内准备或读取文档记忆。运行持有 provider lease，停用后不接收新工作，在途任务完成或取消后释放。
- 宿主传入已固定的文档版本、当前问题、当前已租用的模型，以及当前运行的 AbortSignal。模型凭据不交给插件设置或记忆文件。
- 宿主提供当前文档的描述、逐页图像字节、原文文字、局部记忆的原子读写、进度回调；每个调用都校验工作区、文档版本和运行身份。不得使用模型返回的路径或页码绕过授权。
- 文档记忆与对话摘要使用不同结构，不把阅读任务伪造为用户对话，不改变现有 `MemoryProvider.summarize` 的含义。
- 新增接口为 SDK 向后兼容扩展，SDK 小版本升至 1.1.0；已有 `^1.0.0` 示例插件仍可使用。外部存储适配器保持现有端口契约，插件记忆通过独立宿主持久化入口保存。

## 本地资料与记忆格式

资料保存在 `<workspace>/.reader-workbench/`，原件遵守现有导入/原位置规则。页图像仍使用文档版本缓存；记忆使用独立 `document-memory` 目录。文件名由宿主根据合法标识生成，写入采用临时文件加原子替换，校验目录链接与真实路径。不得覆盖原件。

记忆键包含工作区、文档 ID、文档版本、插件/提示词格式版本、模型配置身份（不包含密钥）。保存：

1. `schemaVersion`、文档标识、页数、模型来源、创建/更新时间。
2. `status`（partial / ready）、实际完成的页码集合、未完成页码、批次记录。
3. 每页的 `page`、主要内容、关键文字/符号、图表描述、公式或数据要点、术语、跨页关系、无法确认的内容；均以文字表示并保留页码。
4. 全文概览、结构索引、关键结论和对应页码。概览不取代逐页记录。

宿主校验模型返回结构、大小、页码与本次批次一致性。覆盖范围由程序根据已提交图像且返回有效逐页结果的批次记录，不相信模型自行声称“已阅读全文”。读不清的页可标记已处理且内容不确定，不能记为已准确识别。

## 首次对话流程

1. 文档解析就绪后，插件按 1 到 N 的顺序准备本地页图像；已存在的有效缓存复用。
2. 检查所选模型声明支持视觉。当前用户指定 `deepseek-flash`；不自动切换模型或修改用户配置。演示/纯文本模型不伪造图像预读成功。
3. 规划一次请求可容纳的页数，计入每页图像、页码提示、记忆输出、工具/协议开销与模型容量。图像 Base64 的请求体增长须按实际编码后 JSON 计算。
4. 全部图像能满足限制时，一次提交所有页。否则顺序分批，使所有页最终均被读取，不能截取前几页后宣布完成。对官方 DeepSeek 采用文档支持的限制；其他兼容服务保持保守默认，可配置。现有四张图像限制改为 provider 级预算检查，不能无条件对所有服务放宽。
5. 预读请求只要求生成有页码的阅读记忆，不执行工具或把文档内容当作指令。模型返回完整成功事件且结果通过校验后，立即保存该批记忆。
6. 全部页完成后生成有来源的全文概览，并将状态原子更新为 ready。
7. 首次用户问题根据已就绪的记忆和对话上下文回答。预读输出不直接成为用户问题的答案，不把页图像灌入永久对话历史。

首次对话等待预读，显示实际进度（已处理页数、当前页码范围、生成概览、开始回答）。大文档不能通过无限累加历史让批次请求超出容量：每批提交对应图像及必要的小型前序索引，全文概览使用有界的分层汇总。

## 后续提问与文档记忆预算

每次请求自动附上文档记忆和所需对话历史。小型记忆完整发送；较大记忆发送全文概览、页码索引与按问题匹配的逐页记录，并提供读取其他记忆页的工具。保留本地全部逐页记忆，不静默截断后宣称本轮包含所有细节。

默认不发送文档页图像，取消现有“每次附第一页”的行为。用户主动截图/选区图像仍按当前意图发送。需要确认某页细节时，模型可使用受控页回看工具，仅补发所需页面，继续记录来源；这个补发能力不能退化为每轮重发全文。图像输入必须进入模型接受的 user 图像消息，不能把 Base64 当普通工具文字或使用不支持的 role。

记忆是可检索的阅读记录，不能承诺无损保存所有图像信息。数字、细小公式或图表存在不确定性时，依据原文文字或局部页图像回查，不能仅凭摘要猜测。

## 版本、并发、取消与失败

- 同一记忆键只建立一份读取任务，防止主/临时对话同时第一次提问造成重复全图读取。建立任务持有独立模型/provider lease 与独立 AbortController，等待者按运行注册；某个等待者取消时退出等待，最后一个等待者退出才取消建立任务。任务结束后释放 lease，不得因一个使用者取消而破坏另一个使用者。
- 使用 partial 批次记录恢复：取消、断网、响应超限或结构校验失败不标记 ready。重试复用已完成页，不重复已完成批次，不将旧版本记忆挪到新版本。
- 文档内容变化按现有版本快照生成新键；模型/插件格式变化生成新键，旧记忆仍可审计。工作区切换不改变在途运行保存位置。
- 对视觉不可用、单页超限、Office 转换缺失、读取失败、磁盘写入失败提供明确错误及已完成页数。失败不能自动退回只看第一页并伪装成全文阅读。
- 默认不逐轮重写整个文档记忆，避免用户问答覆盖原文事实。用户问题/回答继续由现有会话 memory 保存；后续若补充文档阅读证据，更新对应页并保留来源和版本。

## 安装、启停与产品可见性

把新插件加入随包插件列表、设置页安装入口和打包产物，可在所属工作区启用/停用并随重启恢复。工作区首次使用新版本时安装并启用随包插件，已安装实例沿用保存的启停状态，用户主动停用后不自动再启用。只在既有工作区内部插件目录不存在该插件时安装，不覆盖同名自有插件；冲突显示诊断并保留原插件。完成验收需要实际安装并启用到测试工作区；只增加示例目录不算完成。

设置页显示所用视觉模型、预读策略与记忆状态；提供查看按页记忆、失败后重试及重建当前版本记忆入口。已有工作区不被静默更换模型。重建保留旧记忆直到替代结果通过校验；只改变受控记忆缓存，不删除用户原文、历史或附件。

## Git 与版本交付

遵守 `docs/versioning.md`，保留已有 `main` 与 `v0.1.0` 历史。设计文档单独提交。实现使用 `codex/visual-document-memory` 分支；只提交本次明确修改的文件，不清理运行资源或覆盖混合工作。

功能与验证完成后，应用新增功能版本为 `0.2.0`，同步根 `package.json`、`package-lock.json`、运行时版本字段与 CHANGELOG。SDK 的新增向后兼容能力版本为 `1.1.0`，插件独立版本为 `1.0.0`。验收后按既有流程快进合并至 main，创建新的注释标签 `v0.2.0`，不改写旧标签，不自动推送或发布到远程。

模拟协议验证与真实 API 验证分开记录。仓库记录真实 LLM 调用此前被禁用，真实测试须先确认用户当前授权，不借用配置凭据自动发起收费请求。没有真实测试时仍可完成协议验收，但交付明确标注真实 DeepSeek 预读未验证，不将其写成通过。

## 验收

采用合成多页 PDF，首页与最后一页内容不同，包含扫描页、图表页和可提取文字页。

- 首次对话：观测模型请求包含 1 到 N 所有页图像；一批能放下时全部一次发送，超限时分批且没有漏页。
- 第二次与重启后提问：实际模型请求包含本地记忆及历史，默认不含文档页图像，最后一页信息仍可回答并引用正确页码。
- 页回看：只补发被请求的页图像，不重发全文；来源、工作区与版本得到校验。
- 覆盖取消/恢复、结构无效、缺页/重复页、并发建记忆、文档更新、工作区隔离、主临时会话、停用和重载、记忆超预算、非视觉模型及请求体预算。
- 测试实际安装插件、启用后的 consumer 路径和本地保存，而不只测试插件内部算法。
- 执行类型检查、相关单元/集成测试、构建与浏览器测试。真实 `deepseek-flash` 调用与协议测试分别记录；无可用凭据/服务时不得由模拟测试声称真实预读通过。

## 官方依据与范围

DeepSeek `/chat/completions` 无状态，后续仍需显式携带应用 memory；该插件不依赖服务端会话记忆。`deepseek-flash` 支持图像输入，Files API 当前为图片文件，不直接上传 PDF/Office 原件。

- https://api-docs.deepseek.com/zh-cn/guides/multi_round_chat/
- https://api-docs.deepseek.com/zh-cn/guides/vision/
- https://api-docs.deepseek.com/zh-cn/guides/files_api/

本设计只负责文档视觉读取与记忆，不引入其他模型服务、全局资料库或新的部署平台。
