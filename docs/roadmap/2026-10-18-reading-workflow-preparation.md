# Reader Workbench 阅读流程改进：调研与开发准备

日期：2026-10-18（Asia/Shanghai）

状态更新：用户随后明确授权直接实现其余功能与翻译插件，并取消学习联动，不再等待 Skill。本文保留最初调研快照；实施范围以 [批准后的规格](../superpowers/specs/2026-10-18-reading-controls-translation-design.md) 和 [实施记录](2026-10-18-implementation-progress.md) 为准。下文“待讨论”“等待 Skill”和学习联动均属历史提案。

## 1. 本轮需求与纠正

目标：使选择工作区、导入、首次阅读、原文提问、文档记忆检索与后续学习成为连续流程，并让选择控件与工作台既有外观一致。

| 用户要求 | 准备开发的范围 |
| --- | --- |
| 目录难找，希望像 Windows 资源管理器 | 目录树、常用位置/磁盘、地址栏与面包屑、后退/前进、明确的目录选择 |
| 首页及进入工作台后的外观下拉框太丑 | 浅色、石墨灰、墨蓝共用同一套圆角弹出选单；检查展开状态 |
| 模型选择框太丑 | 与外观选择统一；支持较长模型名、连接区分和键盘操作 |
| 思考强度可以不用改 | 保留现有强度控件与行为 |
| 纠正“绘画分级”的误读 | 没有绘画功能需求；涉及外观、模型、对话/临时分支相关选择控件 |
| PDF 已能选字，翻译应复用定位 | 复用真实文字和来源锚点；整篇处理需要持久化文字块几何信息 |
| 主目录的文档记忆检索太简单 | 可检索的公式、图表、术语及知识条目，带版本和来源 |
| 学习组织缺少联动 | 将专题、文档、讨论、问题、笔记和学习进度关联起来；具体首批范围待讨论 |
| 首次阅读按格式分流 | PDF/PPT 使用所选页图像；Markdown/Word 默认发送提取的文本，保留来源结构 |
| 首次总体记忆应能找到具体公式 | 概览之外保留逐条公式索引；支持编号、术语和描述检索后回到原文 |
| 导入时选择初读页数 | 全部、前 N 页、自定义多段，例如 `2-3,10-15`；后续可补读 |
| 后续一键翻译通过插件实现 | 本轮只准备共用接口；用户提供 Skill 后重新核对实现要求 |

用户提到首页“六个选择”，当前入口代码能确认三种外观和多个设置/选择控件；不据此增加六种主题。以用户截图所示外观菜单及上述明确控件为范围。

## 2. 当前实现中已核实的事实

核对对象为当前工作目录文件，包含已有未提交修改；不能把它等同于已发布版本。

| `plugins/visual-document-memory/context.mjs` | 超出预算时按问题片段在页 JSON 中是否出现排序 | 中文长问句、同义表达和公式别名的召回有限 |

| `packages/core/src/sessions/context.ts` | 临时对话继承最新已完成的主对话；选中文字后仍可能追加整页图像 | 文本操作要独立选择输入模态，避免选区翻译不必要地触发全篇视觉预读 |
| `apps/web/src/workbench/DocumentMemoryPanel.tsx` | 只提供状态、按页查看和重建 | 需要搜索、条目视图、覆盖范围、补读和来源跳转 |
| `packages/core/src/plugins/ui-bridge.ts` | 插件视图支持受控 Markdown/plain-text；没有完整文档处理/预览桥 | 翻译插件需小而通用的宿主接口扩展 |

本轮只核对源码与用户截图，没有启动工作台、运行真实模型或重新执行测试。表中机制结论不代表本轮运行验收。

## 3. 推荐分成四个开发包

推荐渐进扩展现有阅读与插件体系。只改外观可以快速修复菜单，但无法解决选页、公式定位和学习断层；直接接入完整记忆框架会增加部署、配置与迁移负担，第一版收益不清楚。

### A. 目录浏览与选择控件

- 目录浏览器采用熟悉的双栏结构：左侧常用位置、最近工作区、可用磁盘/根目录及按需展开的树；右侧当前目录列表。
- 顶部提供后退、前进、上一级、面包屑与可编辑地址栏。可粘贴完整路径；目录名称过滤限定当前目录，避免默认递归扫整块磁盘。
- 单击选择、双击进入；底部持续显示将打开的完整路径。正在加载、无子目录、权限不足、目录已移除均有明确状态。
- 路径、盘符和常用位置由服务端按实际操作系统返回；页面不硬编码用户目录或 Windows 盘符。修正字符串截断父路径的做法，支持盘符根、UNC 和 POSIX 路径。
- 本地 Web 应用先使用服务端目录浏览。浏览器文件系统 API 授予的是浏览器句柄，不能直接替代现有以 Node 服务端路径为身份的工作区。
- 抽取统一的选择组件：闭合按钮和展开选单共享圆角、间距、表面色、悬停/选中/焦点状态。浅色、石墨灰、墨蓝都检查展开效果。
- 主题项用名称、色样与选中标记；模型项区分模型名称与连接名称，列表较长时可检索。临时分支及相关设置项使用同一组件词汇。
- 弹层通过 portal/popover 等方式避开父容器裁切；支持方向键、Enter、Esc、焦点返回及屏幕阅读器语义。
- 保留当前整体布局、三种外观和思考强度。用户要求的一致圆角优先于营销页面的视觉规则。

### B. 首读范围、格式分流与共用文字来源

导入文件以及首次从工作区打开尚未建立阅读计划的文档时，展示简短的“初次阅读范围”。不把它藏在全局设置里，也不在每次重开时重复打断。

- PDF/PPT：全部、前 N 页、自定义范围；解析页数后即可校验。例：`2-3,10-15` 为 8 页，`1-10` 为 10 页。使用阅读器的物理页序号，印刷页码标签另外显示。
- 去重并合并重叠范围；拒绝 0、负数、逆序、越界和空范围。开始前显示规范化结果、选中页数、输入方式与所选模型能力。
- 可以暂不预读，只打开原文。确定范围本身不应悄悄启动远程调用；首次提问或明确点击“开始阅读”才发送。
- PDF/PPT 首次按所选页分批发送图像；后续使用已保存记忆，只按需回看具体页。保留现有分批、输入预算、取消和断点续读机制。
- Markdown 首读发送结构化文本块，保留标题、公式原文、代码、表格与块锚点；没有稳定物理页码时按章节/文本范围选择。
- Word 首读默认发送提取的正文与表格文字；已有转换 PDF 的页文本可作为保留页码来源的首批路径。预览仍可用 PDF；不因此强制要求视觉模型。
- Word 公式/特殊文字提取不完整时标记具体遗漏，不能把提取失败当成没有内容；Markdown/Word 中图片内容未发送时明确记录覆盖限制，需要时再补读图像。
- 原始格式、预览格式与输入模态应分开表示。相同 PDF 预览不意味着 Word 与 PPT 应采用相同首读策略。
- 选区解释/翻译优先走已选文字与锚点，不触发全篇预读。明确请求核实图形时再带相关页面图像。

需要同时调整契约、SDK、宿主消费流程、插件和 API：

- 阅读计划记录请求范围；文档记忆分别记录已覆盖范围、失败范围、未读范围和概览对应范围。
- 完成所选 10 页应显示“初读范围已完成，10/200 页”，不能显示“全文已读”或因未读另外 190 页而阻塞回答。
- 扩大范围只读取缺失页；改变范围不让已完成页失去复用。以文档版本与页/块内容身份保存来源，保留模型和提示版本出处。
- 阅读计划默认理解为首次自动预读范围。后续问题涉及未读页时，明确给出补读入口，不自动扩成全文阅读。
- 原始文本索引、模型阅读记忆和概览的覆盖范围分开标注。程序提取到了文字不等于模型已经阅读了它。
- 旧 schemaVersion 1 记忆保留并兼容读取；升级不伪造旧记忆中不存在的精确坐标。新增范围和条目结构需要显式版本迁移。

### C. 可检索、可回查的文档记忆

概览负责建立结构；逐页/逐块记录保存细节；公式、图表与术语另外建立可检索条目，避免概览压缩掉细节。

建议每个公式条目包含：稳定条目 ID、原文编号（若存在）、原文/LaTeX、所在文档版本、页/文本块锚点、上下文、符号和别名、提取方式、识别不确定项。编号与条目 ID 分开，防止不同文档都出现“公式 3”时混淆。

- 支持“式 (7)”“第 12 页的损失函数”“你刚讲的那个归一化公式”三类检索：编号精确查找、名称/解释匹配、当前对话来源消歧。
- 搜索结果显示公式/片段、文档名、页码或章节、来源类别和匹配信息；点击后定位并高亮。
- 文本层或原生结构给出块 ID/几何位置；模型返回条目语义与块关联。坐标由程序验证，不能由模型凭空编造。
- 已选 PDF 文字当前只有页内整体矩形；跨行或跨栏的细粒度块集合需补充。无法可靠细分时保留页级来源并标注，不能承诺已有逐公式精确框。
- 视觉页中的公式可保存原图区域/页来源及待核对的转写。逐页列式与验收样例检查遗漏；不把“模型输出了几条”当成“全部公式已完整提取”的证据。
- 临时对话第一次提问也能复用或建立文档记忆，不要求先在主对话提问；但学习理解、对话结论与原文事实区分保存。
- 保持临时对话不自动回写主对话。可建议一个“加入学习笔记/主线结论”动作，由用户明确选中后保存带来源的条目。

检索优先复用已有 SQLite，第一批增强中文分词/字符召回、公式编号和别名、元数据过滤、候选合并去重与邻近块扩展。语义向量作为可选能力加入：没有 embedding 服务时基础检索可用；降级状态需要可见。

作用域先过滤再排序：工作区 → 用户选择的专题/文档集合 → 文档版本 → 页/块。默认当前文档，不自动混入其他工作区。静态论文知识不按时间衰减；学习日志可按时间组织。更正以新版本覆盖关系记录，保留原文证据与用户纠正的区别。

### D. 学习联动与翻译插件衔接

推荐第一版学习闭环：专题选择相关文档 → 为当前阅读目标建立主对话 → 从原文/公式发起临时追问 → 将需要保留的结论加入来源笔记 → 记录未解决问题 → 下次继续原文位置与待办。

专题先做工作区内的逻辑集合，不移动用户现有文件。显示三种不同信息：原文位置、AI 记忆覆盖、用户标记的理解状态；不把读过或模型预读过当成已掌握。

本包首批建议只覆盖专题关联、来源笔记、待解决问题、继续学习。跨文档比较和复习安排作为候选，不默认扩大为课程管理系统。是否优先做多文档专题，还是先把单篇文档闭环做完整，需要用户选择。

一键翻译等待用户提供 Skill 后再确定正式规格。可提前共用的基础是：按范围提取正文块、读取真实来源几何、调用已配置模型、任务进度/取消、临时预览、另存输出。

翻译与阅读定位的关系：

1. 选区翻译直接复用 `SelectionContext`，获取所选文字和已知来源。
2. 全篇翻译需要完整且稳定的文字块、阅读顺序与几何。复用 PDF.js 数据，增加持久化；不能依赖用户逐页框选。
3. 模型按块 ID 返回译文；程序校验 ID、漏块、重复、长度及来源。程序负责位置，插件负责翻译任务与排版。
4. 抽取到文字位置并不等于能原位放下译文。双栏、旋转文字、字体、译文扩张、图中文字和表格需要分别验证。

历史翻译约定来自此前讨论，仍需与即将提供的 Skill 核对：插件承载翻译，Markdown 保留图片/链接/公式/代码并另存，Word 保留可编辑性，PDF/PPT 预览与导出采用 PDF；正文、标题、图注及表格文字为范围，公式和图内小字保留；默认不添加重量级 OCR。扫描页不具备文字层时说明该翻译路径不支持。

## 5. 建议增加的功能：候选而非承诺范围

优先推荐前三项，它们直接补齐用户提出的阅读链路。

| 候选 | 用户能做什么 | 依赖 |
| --- | --- | --- |
| 带来源的学习笔记与问题清单 | 把一段解释保存到对应公式/段落下，标记未理解、已解决、待复习，随时回原文 | 条目与来源锚点 |

## 6. 开发顺序与验收准备

建议顺序：A（操作与控件）→ B（首读范围及输入分流）→ C（条目与检索）→ D（学习联动）；翻译插件在用户 Skill 到位后独立设计，复用 B/C 的来源能力。

每个开发包分别形成规格、计划和验收，避免一轮改完所有子系统再检查。已有未提交文件较多，实现前必须逐文件识别既有改动，只暂存本次范围；不要重置、覆盖或把已有文件一起提交。

### 必须覆盖的场景
