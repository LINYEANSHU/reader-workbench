# Translation module delivery (2026-10-18)

Implemented generic `documentProcessor` SDK capability, `DocumentProcessingService`, scoped HTTP task routes, and the installed/copied bundled `document-translation.translate` plugin. Translation prompts, numbered-block protocol, Markdown/DOCX/PDF format decisions and workflow live in the plugin. Host facilities expose scoped source bytes, resources, ZIP transforms, real PDF text geometry, PDF rendering and composition; no host filesystem paths enter task results.

Tasks pin both processor and configured model capability leases, preserve session usage tracking, enforce the model input budget and send no output-token cap. Start/poll/cancel/preview/save check workspace ownership, caller, session, session generation and pinned document version. Selection-only processing bypasses source/visual pre-reading. A cancelled or failed task cannot publish. Explicit save registers an artifact-write scope, uses ArtifactService atomic collision-safe output and releases the scope; preview remains internal until then.

Markdown translation validates every block ID and protected-token order/count, keeps code/math/link destinations/table delimiters, retains YAML metadata, and embeds snapshot image resources as data URIs so the saved document is portable. Tables are recognized by a header and matching delimiter row; only cell text is translated, while source pipe tokens, cell whitespace and the full delimiter row stay outside model control. A translation that adds a cell delimiter or line break is rejected. Ordinary prose pipes and pipes protected inside code or math do not create table cells. Fenced and inline code examples are masked during resource rewriting, so image syntax inside code stays literal and never requests snapshot assets. DOCX translation groups continuous editable text across differently styled runs within a paragraph, then edits only native text nodes at their original XML offsets. Paragraphs, hyperlink ranges, explicit breaks, fields, OMML and media form boundaries; field instructions/results, image binaries and formula XML remain unchanged. DOC uses a LibreOffice-converted DOCX copy. PDF/PPT uses the selected PDF text layer and real block rectangles, copies each original page unchanged, then adds Chinese translation companion pages rendered through the existing DOCX/LibreOffice exporter. Long translations can continue onto additional pages; they are never clipped to source geometry. Textless selected pages fail clearly without OCR.

API prefix: `/api/v1/workspaces/:id/document-processing`. GET lists processors; POST starts `{document,providerId,sessionId,processorId,targetLanguage?,pages?,selection?}`. `GET /:taskId?sessionId=`, `POST /:taskId/cancel {sessionId}`, `GET /:taskId/preview?sessionId=`, `POST /:taskId/save {sessionId,name?}`. Task status is queued/running/ready/cancelled/failed/saved, with progress, warnings, preview file metadata and up to 120000 characters of escaped UI preview text. The preview endpoint returns actual bytes with `Cache-Control: no-store`. Model protocol: system marker `DOCUMENT_TRANSLATION_BLOCKS`, request JSON `{targetLanguage,blocks:[{id,text}]}`, response JSON `{translations:[{id,text}]}`.

Validation includes observed initial RED (new modules absent), subsequent regression RED for table structure and mismatched extensions, and additional observed RED for a word split across styled Word runs, empty self-closing text nodes, field-cache isolation, break boundaries and Markdown code-image examples. The final table regression used valid model responses that prepend `译文：` or `翻译：` while preserving every protected token: before the fix a real MarkdownIt parser found no table; after the fix it finds one table with two header cells and two body cells, with the delimiter row unchanged. Both optional outer pipes and original cell whitespace are covered. The installed-plugin tests exercise real Markdown output, editable DOCX ZIP/XML, original byte preservation and selected-page Chinese PDF generation with LibreOffice 26.2.6.3. A styled DOCX containing `Hel` / bold `lo ` / italic `World.` reaches the model as one `Hello World.` block; its saved editable translation reopens successfully through LibreOffice. Authenticated HTTP tests cover the complete start/poll/preview/save flow, cross-session denial and cancellation. Model responses are deterministic test fixtures, so no production-model translation quality is claimed.

Boundaries: PDF/PPT output is an explicitly labelled source/translation comparison, not inline layout replacement. Word preview-page subsets cannot be mapped exactly to editable DOCX XML; this version rejects them with a clear choice of all pages or text selection. Within each continuous Word text span, the full translation is written to the first editable text node and later text nodes remain editable but empty. Existing run/style XML stays present, while bold, color or other style ranges may no longer align word-for-word with the translation; the output includes this warning. Text length can also change pagination. Markdown images must already be available in the document's versioned resource snapshot; unavailable assets fail rather than silently breaking. Processor tasks/previews are ephemeral and require restarting after server restart. Scanned documents require another workflow; this plugin never installs or invokes OCR.
